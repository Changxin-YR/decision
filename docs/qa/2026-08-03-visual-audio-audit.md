# 2026-08-03 视觉与音效时序审查

## 结论

- 界面按用户要求冻结；浅色与深色首页保持两套独立设计。
- 五个决策流程采用分级时长：是/否 1.4 秒、硬币 2.5 秒、抽签 3.0 秒、罗盘 3.6 秒、指尖选择 3.0 秒。
- 所有五项均先接受过程音播放请求再启动计时，先接受结果音播放请求再显示结果；页面取消会停止当前短音效。

## 根因与修复

- 原 SoundPool 使用通知流，短交互音调度优先级不合适；页面又未等待异步播放请求，导致 UI 先于声音。现改用游戏流、预加载短音效、停止后替换，并保护前后台初始化代次。
- 罗盘和指尖此前仍未等待声音；硬币和抽签的主动画早于结果时间结束，产生空等。现统一时间常量，硬币动画覆盖 2.3 秒，抽签余光覆盖到结果，罗盘固定为 3.6 秒，指尖结果在结果音调度后揭示。
- WAV 无前置静音：tap 约 70ms、coin 约 160ms、draw 约 200ms、wheel 约 180ms、result 约 280ms。过程与结果间隔均远大于音效本身，且结果音会替换仍在播放的过程音。
