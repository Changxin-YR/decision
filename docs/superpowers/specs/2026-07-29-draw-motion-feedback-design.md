# 抽签动作与反馈优化设计

## 目标

优化抽签过程的动作表现，补强可感知的音效与震动反馈，同时保持现有抽签概率、不重复抽取逻辑、历史记录和模板存储行为不变。

本轮同时回归转盘手动选项持久化：用户输入选项后转动、关闭结果并再次转动时，Canvas 和下方输入框必须始终保留原值。

## 抽签动作

采用已批准的 C 方案“强仪式感”，单次动作总时长约 2 秒：

1. `0–420ms`：签筒进行五次渐弱左右摇动，并叠加轻微上下位移。
2. `420–560ms`：签筒回正并短暂停顿，形成抽出前的悬念。
3. `560–1450ms`：签条快速抽出，超过目标位置后轻微回落。
4. `1450–2000ms`：签条文字高亮并稳定展示，随后显示结果弹层。

签筒与签条使用独立变换。签筒可以摇动，签条及其文字不得跟随旋转而倾斜或镜像，确保结果始终正向可读。

## 音效与震动

反馈继续服从设置页的“音效”和“振动反馈”开关：

- 动作开始：播放 `draw.wav`，触发 `18ms` 轻震。
- 最后一次摇动：触发 `28ms` 中震。
- 结果落定：播放 `result.wav`，触发 `70ms` 结果震动。

音效或震动 API 调用失败时不影响抽签完成。页面进入后台、离开页面或动画被取消时，必须停止后续计时反馈并恢复静止状态。

音效链路需要保留失败可观测性，避免底层播放错误被完全静默吞掉；日志不得包含用户输入的选项内容。

## 状态边界

- `DrawSession` 继续负责预选结果、完成、取消和剩余选项，不承载动画状态。
- 抽签页面负责动作时间线、反馈触发和结果弹层。
- `DrawTube` 只负责渲染签筒、签条和高亮状态。
- 动画开始前对选项做现有校验和标准化。
- 动画期间禁用再次抽签、编辑和返回操作。
- 结果关闭或点击“再试一次”不得清空原始选项。

## 转盘持久化回归

转盘继续使用页面内响应式 `wheelOptions` 快照向 Canvas 提供文字。编辑、增删、排序和旋转前均同步快照，结果生成和关闭结果弹层不得重建为空白草稿。

设备验收流程：

1. 在空白转盘手动输入两个新选项。
2. 确认 Canvas 即时显示两个选项。
3. 开始转动并等待结果。
4. 关闭结果弹层，确认 Canvas 和两个输入框仍保留原值。
5. 不重新输入，直接再次转动并正常得到结果。

## 测试

- 新增纯逻辑动作时间线测试，覆盖总时长、阶段顺序和三次震动触发点。
- 新增反馈开关测试，关闭音效或震动时不得触发对应服务。
- 保留并运行全部现有 Hypium 测试。
- 在 API 24 phone 模拟器验证动画不跳帧、文字正向、结果弹层时机和后台取消。
- 使用手动输入选项完成两次连续转盘设备测试。

## 非目标

- 不修改随机算法、抽签概率或不重复抽取规则。
- 不新增在线资源、权限或持久化字段。
- 不改变现有视觉主题和主要页面布局。
