# 夜间模式视觉还原设计

## 目标与边界

仅在深色主题（含“跟随系统”处于深色时）还原用户提供的四张参考稿视觉。范围覆盖首页、幸运转盘、抽签、指尖选择、抛硬币、是或否和随机数字，以及它们共享的页面标题、卡片、输入、选项编辑和按钮。

浅色主题、页面路由、现有可滚动结构、响应式宽度限制、可访问热区、随机算法、动画时序、设置/模板/历史持久化和反馈服务均不改变。现有工作区的反馈修复不在本任务改动范围内。

## 方案

采用“深色主题专用视觉层”：扩展主题令牌以提供参考稿所需的深海军蓝底色、蓝黑半透明表面、冷蓝描边、亮蓝按钮和光晕阴影；共享组件消费这些令牌；各页面只添加参考稿独有的深色尺寸、渐变、光效和插画排版。避免用位图覆盖交互页面，也避免在每个页面复制主题判断。

## 页面映射

- 首页：两列工具入口与模板列表保留；深色卡片、工具/模板插画、标题区和历史/设置入口匹配参考图 1。
- 转盘：保留画布、选项编辑器、保存模板和结果流程；深色轮盘使用高对比扇区、顶部蓝色指针、中心冷光按钮和蓝色主操作，支持参考图 1、3、4 的 2–6 选项状态。
- 抽签：保留重复开关、抽签动效、选项编辑和保存；深色主题下以蓝紫抽签筒插画、蓝色描边控件和主按钮匹配参考图 1、3、4。
- 指尖选择：保留全屏多指触控与结果状态；引导文字、主体手势插画和底部操作匹配参考图 2。
- 抛硬币：保留正反面统计、抛掷与问题输入；深色卡片、硬币主体、操作层级匹配参考图 2。
- 是或否：保留问题输入、两个直接选择按钮和“交给直觉”；深色背景、蓝色“是”圆按钮和弱化“否”按钮匹配参考图 2。
- 随机数字：保留范围设置、开关、预设、结果和生成动作；深色表面、输入框和蓝色高亮匹配参考图 3。

历史、设置和隐私页不改变信息或交互，仅通过共享深色令牌获得同一视觉体系。

## 组件与数据流

`ThemeResolver` 继续是深浅色切换的单一入口。`AppCard`、`AppButton`、`AppInput`、`PageHeader`、`OptionsEditor` 和决策插画组件接收既有 `ThemeTokens`，不读取设置仓储、不处理导航、也不改变回调。页面继续调用现有 domain/state/service 模块。

新增的视觉令牌仅描述颜色、渐变、边框、阴影、圆角和间距；它们不得引入持久化字段、业务状态或随机行为。

## 异常与兼容性

缺失插画资源时保持现有组件可渲染，不阻塞决策流程。phone 竖屏仍是像素还原目标；720vp 内容上限与系统安全区行为保持，tablet/foldable 仅做代码适配、不宣称设备实测。

## 验证

先为深色主题令牌和关键视觉条件补充可运行回归断言，再验证全部既有单元测试。执行 `scripts/check-standard.ps1`、主 HAP 与测试 HAP 构建；如现有 API 24 phone 模拟器可用，采集深色主题首页、转盘、抽签和至少一个简单决策页的截图至 `docs/qa/`。在 `design.md`、`changes.md` 和 `design-qa.md` 记录实际实现与验证结论，不伪造设备结果。
