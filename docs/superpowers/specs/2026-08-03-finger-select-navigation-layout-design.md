# 指尖选择页导航与触控区优化设计

## 目标

调整 `FingerSelectPage` 的非业务 UI：统一返回键样式，删除底部小提示，把“重新开始”和“返回首页”下移至动态导航安全区上方，并让多指识别覆盖除这三个控件之外的页面主体。

## 范围与约束

- 不修改 `FingerSelectionMachine`、倒计时、随机选中、音效、振动或路由回退逻辑。
- phone 竖屏为布局基准；宽屏继续遵守页面现有的 720vp 最大宽度。
- 浅色和深色主题均使用 `ThemeTokens`，不引入固定主题颜色。
- 底部位置基于已经由根 `Navigation` 消费的动态 `bottomSafeAreaPx`，不使用设备型号或固定状态栏高度。

## 已确认的方案

1. 顶部使用与其他页面一致的卡片式返回键视觉，尺寸为 44vp，圆角、文字色和卡片色继续来自现有设计令牌和主题令牌。
2. 移除“小提示”文本。按钮组通过底部布局间距下移约 5% 的 phone 屏高；其父导航容器已经为动态系统导航安全区预留内边距，因此按钮不会侵入导航区。
3. 将指尖识别的触摸事件从全页根 `Stack` 移入单独的主体触控层。该层从页首内容下方延展到按钮组上方；返回键、“重新开始”和“返回首页”均位于触控层外，保持只响应自身点击。

## 实现边界

- `FingerSelect.ets`：组合 `PageHeader` 或等效的同视觉返回键，调整底部列布局，新增主体触控层并绑定现有 `updateTouches`。
- 如现有 `PageHeader` 的公开属性不能安全表达 44vp 紧凑尺寸，只扩展该组件的可选尺寸参数，默认值保持所有现有页面不变。
- `DesignTokens.ets`：仅在需要共享 44vp 紧凑返回键尺寸时新增令牌；不重排无关令牌。
- 静态检查：验证该页不再包含小提示、不会在根容器监听触摸、仍使用动态安全区路径以及按钮回调保持不变。

## 验证

1. 运行 `scripts/check-standard.ps1` 和更新后的针对性静态检查。
2. 构建主 HAP 与测试 HAP：`scripts/build-harmony.ps1`。
3. 若 phone API 24 模拟器可用，验证浅色/深色两种主题：返回键可返回、主体两指可倒计时、三个控件不触发识别、按钮完整位于系统导航区上方；保存截图或结构化证据到 `docs/qa/`。
