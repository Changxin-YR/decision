# “做个决定”UI 像素级还原设计

## 1. 目标

在不改变现有功能语义、随机算法、持久化和导航行为的前提下，将原生
HarmonyOS Stage/ArkTS 应用的手机竖屏界面还原为
`C:\Users\27363\Desktop\decision_jpg` 中的 12 张设计稿。

手机竖屏以设计稿为逐像素验收基准。tablet 继续使用相同组件与数据流，
只要求布局完整、操作可达和内容不溢出，不要求与手机稿逐像素一致。

## 2. 范围

### 2.1 包含

- 重构 `pages/`、`components/`、视觉令牌和媒体资源。
- 还原安全区、页面头部、内容层级、间距、字号、颜色、圆角、阴影、图标、
  插画、卡片、按钮、输入框、开关和列表。
- 保留并重新接入现有运行态、禁用态、校验错误、空状态、结果态和确认弹层。
- 对手机模拟器逐页截图，与设计稿进行视觉比对并迭代。
- 将实现、构建和截图结果交给现有 VS Code/Claude Code 环境复核，并处理反馈，
  直到得到明确通过信号。

### 2.2 不包含

- 不新增或删除产品功能。
- 不修改随机结果规则、历史记录语义、设置语义或 Preferences 数据格式。
- 不要求 tablet 与手机设计稿逐像素一致。
- 不使用整页截图覆盖交互界面。

## 4. 架构

保留以下现有模块及职责：

- `domain/`：随机算法、校验和状态机。
- `stores/`：应用状态与草稿状态。
- `services/`：声音、触感、剪贴板和生命周期。
- `data/`：Preferences 与仓库。
- `models/`：导航和领域模型。

UI 改动限定在以下边界：

- `constants/DesignTokens.ets`：统一视觉令牌。
- `components/common/`：页面头部、按钮、卡片、输入、分组、结果与确认组件。
- `components/decision/`：转盘、抽签盒、硬币和选项编辑器。
- `pages/`：按设计稿编排页面，接回原有功能事件。
- `resources/`：生产位图与应用资源。

## 5. 视觉系统

- 以设计稿的冷白背景、深色主文字、蓝色主操作和低饱和功能色为准。
- 手机内容使用固定的水平节奏、紧凑卡片和明确的上下分组，不引入装饰性嵌套卡片。
- 主操作使用设计稿中的蓝色渐变、白色文字和轻量阴影；次操作使用白底、
  细边框或透明背景。
- 页面头部、设置分组、历史行、模板行、选项编辑器、结果卡片和底部操作
  使用共享组件，避免页面间的尺寸漂移。
- 图标优先使用 HarmonyOS 可稳定渲染的资源或位图，不使用 emoji 作为生产图标。
- 抽签盒、硬币和指尖引导等图像资源使用 image2/imagegen 生成或从已批准设计源
  派生，保存原始源图、提示词、裁切信息、最终资源名、尺寸和用途清单。

## 6. 页面与组件

### 6.1 首页

还原大标题、历史/设置图标按钮、六个两列工具卡片、快速模板列表和底部隐私说明。
模板点击继续复用现有草稿写入与路由逻辑。

### 6.2 转盘与抽签

共用页面头部、主操作按钮、选项管理和保存模板组件。标题、副标题、候选项和转盘
分区由模板数据驱动。转盘动画和抽签状态机保持不变。

### 6.3 指尖选择

空闲态按设计稿显示指尖引导插画、说明和底部操作。触点、倒计时和选中态继续由
现有状态机覆盖在交互区域内。

### 6.4 抛硬币、随机数字和是或否

按设计稿重排统计、输入、结果、历史和底部操作。硬币翻转、数字生成、结果保存
和问题文本继续使用现有逻辑。

### 6.5 历史与设置

历史记录按设计稿提供筛选条、日期分组和紧凑记录行；设置使用分组卡片、图标、
开关和分段主题控件。删除、清空、主题与隐私入口行为保持不变。

## 7. 数据流与异常

页面输入继续进入现有 store 或 state machine；随机服务在动画前确定结果；
历史和设置继续通过仓库写入 Preferences。

以下状态必须保留并符合新视觉：

- 动画期间的禁用和重复提交保护。
- 草稿离开确认。
- 选项与数字范围校验错误。
- 空历史、抽签耗尽和无结果状态。
- 保存失败提示与删除确认。
- 应用进入后台后的动画和计时取消。

## 8. 验收

### 8.1 自动化

- 运行标准化静态门禁。
- 构建并运行现有 Hypium 测试。
- 构建 API 24 Debug HAP。
- 运行 `git diff --check` 和必要的权限/跨端扫描。

### 8.2 视觉

- 在手机模拟器以设计稿对应的竖屏视口逐页截图。
- 先比较安全区、头部、主内容和底部操作，再比较字号、间距、颜色、圆角、
  阴影、图标和插画。
- 对设计稿与运行截图进行同尺寸叠加或像素差分；差异必须能够由动态内容、
  系统状态栏或已记录的平台渲染差异解释。
- tablet 验证内容完整、交互可达、长文本不溢出和滚动可用。

### 8.3 Claude Code 复核

向现有 VS Code/Claude Code 会话提供改动摘要、构建结果、测试结果、设计稿映射
和运行截图。将反馈映射到具体页面或质量问题，修复后重新执行相关测试、全量构建
和视觉比对。只有 Claude Code 明确返回通过信号，且最新代码通过本地验证，才完成交付。

## 9. 风险控制

- 设计稿包含系统状态栏，应用内容验收时单独区分系统绘制区域。
- 位图资源需同时检查浅色背景、深色主题、缩放和圆角裁切。
- 设计稿展示的是部分数据状态，未展示的动态结果态沿用同一视觉规则，不擅自改变功能。
- 若模拟器或 VS Code/Claude Code 会话不可用，必须记录真实阻塞条件，不把构建通过
  表述为设备视觉验收通过。
