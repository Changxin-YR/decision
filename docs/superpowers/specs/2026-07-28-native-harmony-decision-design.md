# “做个决定”原生鸿蒙应用设计

## 1. 目标

将《FUNCTIONAL_SPEC.md》和《V1_DEVELOPMENT_DOC.md》描述的“做个决定”v1.0 实现为可真实安装、离线使用的原生 HarmonyOS 应用。

产品功能和交互规则以两份原始文档为方向；原开发文档中的 React Native、Expo、TypeScript、AsyncStorage 等跨端技术要求全部替换为 HarmonyOS API 24 对应的原生 ArkTS、ArkUI 和系统能力。

## 2. 范围

### 2.1 包含

- 六个决策工具：幸运转盘、抽签、指尖选择、抛硬币、是或否、随机数字。
- 四个内置模板和用户自定义模板。
- 历史记录的保存、查看、复用、单条删除、全部清除和 200 条上限。
- 振动、音效、系统/浅色/深色主题、自动保存历史和本地数据清理设置。
- 隐私说明和使用说明。
- 手机、折叠屏、小屏和系统大字体下的自适应布局。
- API 24 工程配置、自动化测试、构建说明和验收文档。

### 2.2 不包含

- 用户系统、网络请求、云同步、广告、付费、会员和消息推送。
- AI、社区、模板分享、选项权重和复杂概率。
- 跨端框架、WebView 页面或 React Native 兼容层。

## 3. 技术约束

- 目标 API：HarmonyOS API 24。
- 语言：规范 ArkTS。
- UI：ArkUI 声明式开发范式。
- 工程：Stage 模型，单 `entry` HAP 模块。
- 持久化：Preferences，仅保存应用设置、自定义模板和历史记录。
- 权限：不声明网络、相机、相册/存储、麦克风、定位或通讯录权限。
- 随机结果必须在动画开始前确定；动画不得参与结果计算。
- 动画或倒计时期间禁止重复提交、编辑关键输入和直接离开页面。
- 应用进入后台时终止当前动画、音效和倒计时；回到前台时恢复页面初始交互态，不产生后台结果。

## 4. 工程结构

```text
entry/src/main/ets/
├── entryability/               # UIAbility 与生命周期
├── pages/                      # 页面入口
├── components/
│   ├── common/                 # 按钮、卡片、输入、弹窗、Toast
│   └── decision/               # 选项编辑器、结果面板、工具图形
├── domain/
│   ├── random/                 # 唯一随机入口
│   ├── validation/             # 选项和数字校验
│   └── state/                  # 转盘、抽签、指尖选择等状态机
├── data/
│   ├── repositories/           # 设置、模板、历史仓储
│   └── preferences/            # Preferences 底层读写
├── services/                   # 振动、音效、剪贴板、生命周期事件
├── models/                     # 领域模型与页面参数
├── constants/                  # 颜色、间距、文案、限制和内置模板
└── utils/                      # 时间格式、ID、通用纯函数
```

每个文件只承担一类职责。页面不直接读写 Preferences，也不自行调用随机数；它们通过仓储和随机服务完成业务操作。

## 5. 页面与导航

应用使用原生 `Navigation` 维护页面栈。

- 首页：六个工具卡片、历史入口、设置入口、内置与自定义模板。
- 幸运转盘：标题、Canvas 转盘、选项编辑、模板保存、结果面板。
- 抽签：标题、重复模式、签筒动画、选项编辑、剩余选项状态、结果面板。
- 指尖选择：全屏多点触控、三秒稳定倒计时、随机选中、三秒结果锁定。
- 抛硬币：正反统计、翻转动画、结果保存和统计重置。
- 是或否：可选问题、圆形决定按钮、是/否结果和记录保存。
- 随机数字：范围、数量、重复模式、校验、结果复制和记录保存。
- 历史记录：倒序列表、详情、复用、删除和清空。
- 设置：体验、外观、数据、关于。
- 隐私说明：纯文本滚动页。

页面参数使用明确的 ArkTS 模型传递。模板或历史复用仅把工具类型、标题和候选项带入对应页面。

## 6. 领域逻辑

### 6.1 随机服务

所有随机行为统一通过 `RandomService`：

- `pickOne`：从非空集合公平选择一个元素。
- `pickMany`：支持有放回和无放回抽取。
- `randomBoolean`：等概率生成两种结果。
- `randomIntegers`：在闭区间内生成一个或多个整数。

无放回随机整数不得构造最多 1,999,999 个元素的大数组；采用集合采样或局部洗牌，确保最大合法范围下仍可用。

### 6.2 结果与动画

- 转盘先选中结果下标，再计算指针所需停止角度。
- 抽签先选中当前候选项，再播放签筒和签条动画。
- 硬币先确定正反面，再计算最终旋转角度。
- 是或否先确定布尔结果，再播放按钮反馈和结果淡入。
- 指尖选择在倒计时完成的瞬间，从仍处于激活状态的触点 ID 中选择结果。

### 6.3 校验

- 转盘和抽签至少两个、最多十二个非空且去除首尾空白后互不重复的选项。
- 单个选项和模板名最多十五个字符。
- 随机数字范围为 `-999999` 至 `999999`，数量为 `1` 至 `100`。
- 无放回抽取数量不得超过闭区间内可用整数数量。
- 错误在当前页面展示并阻止动画或持久化操作。

## 7. 数据模型与持久化

### 7.1 设置

保存音效、振动、主题模式和自动保存历史。缺失或损坏的数据回退到默认值。

### 7.2 模板

内置模板写在常量中且不可删除。Preferences 只保存自定义模板；模板包含 ID、名称、工具类型、选项和创建时间。

### 7.3 历史

记录包含 ID、工具类型、标题、候选项、结果和创建时间。新记录置顶；超过 200 条时裁剪最早记录。

仓储对解析错误、写入失败和旧版本字段缺失做安全回退，并向页面返回可展示的失败结果，避免静默误导用户。

## 8. 设计系统和自适应

- 浅色背景 `#F5F5F5`，卡片 `#FFFFFF`，主文字 `#1A1A1A`。
- 深色背景 `#2C2C2C`，卡片 `#3A3A3A`，主文字 `#F0F0F0`。
- 主题强调色 `#4A90D9`，成功色 `#27AE60`，错误色 `#E74C3C`。
- 输入框圆角 8vp；按钮和卡片 12vp；结果面板 20vp。
- 页面标题 24fp；功能标题 20fp；正文 16fp；辅助文字 13fp。
- 交互使用 vp/fp 和约束布局，不依赖固定像素。

直板手机首页使用两列卡片；大窗口和折叠屏展开态根据可用宽度增加列数，并限制主要内容最大宽度。可滚动页面必须在小屏和大字体下保持所有操作可达。尺寸变化不清空已输入内容或当前非动画业务状态。

## 9. 错误与生命周期

- 防止快速重复点击：业务状态先切换到运行态，再启动异步动画。
- 动画期间禁用相关输入和按钮，并拦截返回操作。
- 进入后台时取消计时器和动画，停止音效，丢弃尚未展示的结果。
- 回前台后页面处于可重新开始的初始交互态。
- 清除历史、清除模板和清除全部数据必须二次确认。
- 本地存储失败时展示简短提示，不宣称保存成功。
- 无音频或振动能力时静默降级，核心决策功能继续可用。

## 10. 测试与验收

### 10.1 自动化测试

使用 Hypium 覆盖：

- 随机选择的边界、无放回唯一性和随机整数范围。
- 选项、模板名和数字输入校验。
- 历史记录倒序与 200 条裁剪。
- 抽签重复/不重复模式状态。
- 指尖选择的倒计时重置和锁定状态机。
- 设置默认值、更新、清除和损坏数据回退。
- 转盘结果下标与停止角度映射。

### 10.2 构建验证

- ArkTS 静态检查无错误。
- API 24 Debug HAP 通过 Hvigor 构建。
- `module.json5` 不包含受禁止的权限。
- 仓库不包含密钥、签名文件或生成包。

### 10.3 交互验收

按照原始功能规格逐项验证六个工具、模板、历史、设置、深色模式、后台恢复、小屏、大字体和折叠屏尺寸变化。

## 11. 完成与外部复核

每个可验证阶段完成后执行测试和构建，提交并推送至 Gitee。全量实现通过本地检查后，在现有 VS Code/Claude Code 环境中发送完成信号并请求项目复核。

Claude Code 返回的问题按以下循环处理：

1. 将反馈映射到具体需求或质量问题。
2. 先补充失败测试或可复现步骤。
3. 实现修复并重新执行相关测试、全量测试和构建。
4. 提交并推送修复。
5. 再次请求复核。

只有在 Claude Code 明确返回完成信号，且最新提交通过本地验证后，项目才进入最终交付状态。
